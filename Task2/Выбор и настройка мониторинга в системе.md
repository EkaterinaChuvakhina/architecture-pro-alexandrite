### Мотивация
 - Мониторинг бизнес-метрик и инфраструктуры покажет узкие места в системе, что поможет сократить время обработки заказов
 - Мониторинг поможет понять какие сервисы необходимо масштабировать, это позволит избежать избыточных расходов на инфраструктуру 
 - Мониторинг авто-алертами снизит риски ошибок в проде и если они возникнут, то увеличит скорость разрешения инцидентов, предотвратит потерю контрактов и клиентов

 ### Выбор подхода к мониторингу
1. API и backend-сервисы (Shop API, CRM API, MES API)  
   Выбранный подход: RED   
   Эти компоненты обрабатывают запросы, поэтому критичны метрики запросов: количество запросов, количество неудачных запросов в секунду и количество времени, которое уходит на выполнение одного запроса. Прост в реализации и фокусируется на пользовательском опыте.
2. Инфраструктура и базы данных (Инстансы приложений, CRM API, MES API, Shop DB, MES DB, S3)
   Выбранный подход: USE  
   Здесь проблемы в ресурсах (перегрузки, медленные запросы в DB для дашборда MES)  
    Выбранный подход: USE 
3. RabbitMQ  
   Выбранный подход: USE и RED  
   USE подойдёт для ресурсов (utilization памяти брокера, saturation длины очередей >1000, errors в доставке)  
   RED для метрик сообщений (rate publish/consume, errors в ack, duration обработки)  
4. Фронтенд-приложения (Internet Shop, CRM, MES)  
   Выбранный подход: Четыре золотых сигнала  
   Четыре золотых сигнала ориентирован на измерение реального пользовательского опыта, позволяют учитывать latency (сеть, браузер, рендеринг), клиентские ошибки и деградацию интерфейса под нагрузкой  

### Метрики
| Система                    | Метрика | Зачем нужна (что показывает метрика и какие выводы можно сделать)                                                               | Ярлыки |
|----------------------------|---------|---------------------------------------------------------------------------------------------------------------------------------|--------|
| RabbitMQ                   | Number of dead-letter-exchange letters in RabbitMQ | Показывает количество сообщений при обработке которых возникла ошибка, позволят сделать выводы о сбоях систем                   | queue_name, reason |
| RabbitMQ                    | Number of message in flight in RabbitMQ | Показывает количество сообщений в активной обработке, позволяя сделать выводы о перегрузке очередей при росте данных.           | queue_name, consumer_tag |
| RabbitMQ                    | Queue length in RabbitMQ (дополнительная) | Показывает длину очередей и бэклог, позволяя сделать выводы о скорости обработки сообщений                                      | queue_name, topic |
| Shop API, CRM API, MES API | Number of requests (RPS) for [system] API | Показывает количество запросов в секунду, позволяя сделать выводы о пиках нагрузки и корреляции с ростом.                       | endpoint, method, user_type (для Shop); <br/>endpoint, method, user_role (для CRM); <br/>endpoint, method, model_complexity (для MES) |
| Shop API, CRM API, MES API | CPU % for [system] API | Показывает уровень использования CPU, позволяя сделать выводы о нагрузке на компонент                                           | instance_id, container_name |
| Shop API, CRM API, MES API | Memory Utilisation for [system] API | Показывает использование памяти приложением, позволяя сделать выводы об утечках                                                 | instance_id, heap_type |
| Shop API, CRM API, MES API | Response time (latency) for [system] API | Показывает время отклика, позволяя сделать выводы скорости обработки запроса.                                                   | endpoint, http_code, percentile |
| Shop API, CRM API, MES API | Number of HTTP 200 for [system] API | Показывает успешные запросы.                                                                                                    | endpoint, method |
| Shop API, CRM API, MES API | Number of HTTP 500 for [system] API | Показывает серверные ошибки, позволяя сделать выводы о сбоях.                                                                   | endpoint, error_type |
| Shop API, CRM API, MES API | Number of simultanious sessions for [system] API | Показывает одновременные сессии, позволяя сделать выводы о пиковых нагрузках.                                                   | user_type (для Shop); user_role (для CRM, MES) |
| Shop API, CRM API, MES API | Kb tranferred (received) for [system] API | Показывает входящий трафик, позволяя сделать выводы об узких местах в передаче по сети.                                         | endpoint, direction |
| Shop API, CRM API, MES API | Kb provided (sent) for [system] API | Показывает исходящий трафик, позволяя сделать выводы о дисбалансе и эффективности доставки.                                     | endpoint, direction |
| Shop DB, MES DB            | Memory Utilisation for [system] db instance | Показывает использование памяти, позволяя сделать выводы об утилизации RAM базой данных.                                        | db_instance, query_type |
| Shop DB, MES DB            | Number of connections for [system] db instance | Показывает количество соединений, позволяя сделать выводы о количестве подключений.                                             | connection_type, source_api |
| Shop DB, MES DB            | Size of [system] db instance | Показывает размер БД, позволяя сделать выводы о росте данных и необходимости масштабирования.                                   | Нет |
| Frontend (Shop, CRM, MES)  | Page load time | Показывает время загрузки страниц (e.g., дашборд MES), позволяя сделать выводы о UX-задержках и влиянии на операторов/клиентов. | page_name, browser_type, device_type |
| Frontend (Shop, CRM, MES)  | Client-side errors | Показывает JS-ошибки в UI, позволяя сделать выводы о багах и их частоте.                                                        | error_type, component_name, user_role |
| Frontend (Shop, CRM, MES)  | Render time for components (дополнительная) | Показывает время рендера элементов, позволяя сделать выводы о производительности UI.                                            | component_type, device_type, percentile |
| Дополнительные (общие)     | Error rate for API endpoints (дополнительная) | Показывает уровень ошибок, позволяя сделать выводы о сбоях и рисках в API.                                                      | api_name, endpoint, error_code |
| Дополнительные (общие)     | Cache hit ratio for DB queries (дополнительная) | Показывает эффективность кеша, позволяя сделать выводы о неэффективных запросах и latency в дашбордах.                          | db_instance, query_type |
